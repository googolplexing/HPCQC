lumi-hpc-qc

Version 1.1.0 · 2026-04-03 · 100+ Python files · ~16,000 lines · LUMI (CSC Finland) + VTT Q50 · + SPEC-002 §7.5 sweep harness in progress (2026-05-26)

A modular framework for running Variational Quantum Algorithms and systematic noise characterisation on the LUMI supercomputer (AMD MI250X GPUs) and the VTT Q50 quantum processor via FiQCI. Researchers define experiments in YAML; the framework handles placement solving, noise decomposition, HDF5 storage, and Parquet export for ML training data.

v1.1.0 — Phase E complete. The sweep engine is operational: YAML config → VF2 placement solving → 11-environment twin simulation → HDF5 → 61-column Parquet. 764 validation checks, zero failures. All 22 VE criteria satisfied. Ready for production sweep campaigns on Q50.

Motivation & background

Noise characterisation on quantum hardware requires running the same circuit across every valid physical qubit layout, under multiple noise regimes, with multiple random seeds. On a 53-qubit device like VTT Q50, a 4-qubit circuit has 487 valid placements. With 11 noise environments and 20 seeds, that's ~107,000 simulations — the noise atlas that ML models need to predict QPU behaviour from calibration data alone.

This framework automates the entire pipeline: from a single YAML config to a Parquet training table that ML teams can ingest directly. The researcher never writes Python code, never touches SLURM scripts, never manages file formats.

Sweep engine overview

The sweep engine takes a YAML config and produces a complete noise atlas: every valid physical qubit layout on the device, under 11 noise environments, across multiple seeds and calibrations. The output is a flat Parquet training table for ML models.

One command, one YAML file, one Parquet table. The researcher defines what to sweep; the engine handles placement solving, noise decomposition, HDF5 storage, and export. No Python code required. 
YAML config
  → Grid expansion (hamiltonians × topologies × seeds × calibrations)
  → E1: VF2 placement solver (all valid placements per device)
  → E4: Twin simulator (11 noise environments per placement)
  → E2: Tiered execution (CPU ≤8q, GPU ≥10q, 128-way parallel)
  → E3: HDF5 writer (WAL crash safety, noiseless deduplication)
  → E8: Export (61-column Parquet + summary CSV)

Sweep YAML configuration

sweep:
  experiments:
    - type: characterization
      hamiltonians: [tfim]
      qubit_sizes: [4]
      topologies: [4q_chain, 4q_star]
      seeds: 20
      noise_configs: all           # all 11 environments
      placement: all_valid         # every VF2-found placement

  calibrations:
    - examples/q50_calibration_20260330.json

  execution:
    cpu_workers: 4

  output_dir: results/sweep_output
  sweep_id: my_sweep_001

Noise source axis (SPEC-002 §7.5 / D3)

Each NoiseConfig carries a source: "channels" (the default — the 11 synthetic depolarizing/T1/T2/readout tiers above, run by the density_matrix twin battery) or "device_calibrated" (real Q50 T1/T2/ readout/CZ calibration, built by backends/device_noise under a pinned statevector method). The eleven channel tiers are unchanged. device_calibrated is opt-in by name — noise_configs: all means the channel tiers only, so it is never silently injected into an existing sweep; request it explicitly (noise_configs: [device_calibrated, noiseless]).

device_calibrated pins statevector. Setting method: density_matrix on a device_calibrated config is rejected with an explanation: the statevector pin is the Kraus-precompute correctness fix (DEBT D2) and the scalable O(2n) path, not a preference. A density_matrix device-calibrated mode is a separate future increment. The device_calibrated name resolves and validates today (D3.3); executing it requires the BYO counts path (D3.4, in progress) — until then the engine refuses it loudly rather than running it through the channel battery.

Synthetic calibrations

Generate perturbed calibration files for sensitivity analysis, future device projection, and anomalous qubit detection:

# Scale T1 by 0.7 (30% degradation)
python -m lumi_hpc_qc.data.tools.perturb_calibration \
    examples/q50_calibration_20260330.json \
    --perturb t1 --factor 0.7 \
    --output calibrations/synthetic_t1_degraded.json

# Set all qubits to identical noise (remove diversity)
python -m lumi_hpc_qc.data.tools.perturb_calibration \
    examples/q50_calibration_20260330.json \
    --uniform-noise --t1 25.0 --t2 12.0 \
    --output calibrations/synthetic_uniform.json

# Project to a future 2× better device
python -m lumi_hpc_qc.data.tools.perturb_calibration \
    examples/q50_calibration_20260330.json \
    --improve-all --factor 2.0 \
    --output calibrations/synthetic_future_2x.json

Every output JSON carries _synthetic_metadata provenance. Physical constraints enforced: T2 ≤ 2*T1, readout fidelity clamped to [0.5, 1.0].

Adding a Hamiltonian

# src/lumi_hpc_qc/plugins/hamiltonians/my_model.py

from lumi_hpc_qc.plugins.hamiltonians.base import HamiltonianBuilder
from lumi_hpc_qc.types import ExperimentConfig, HamiltonianMetadata
from qiskit.quantum_info import SparsePauliOp
import numpy as np

class MyModelHamiltonian(HamiltonianBuilder):
    name = "my_model"                      # ← used in YAML: model: my_model

    def build(self, config: ExperimentConfig):
        p = config.model_params
        terms = [("ZZ", p.get("coupling", 1.0)), ("XI", p.get("field", 0.5))]
        ham = SparsePauliOp.from_list(terms).simplify()
        meta = HamiltonianMetadata(
            num_qubits=ham.num_qubits,
            pauli_term_count=len(ham),
            description="My model description",
        )
        return ham, meta

    def exact_ground_energy(self, hamiltonian):
        if hamiltonian.num_qubits > 24:
            return None
        return float(np.real(np.linalg.eigvalsh(hamiltonian.to_matrix())[0]))

BYO circuits

HPCQC ingests researcher-supplied circuits in two modes:

Mode 1 — fixed circuits (evaluation-only)

A single, non-parameterized circuit, run once per placement per noise config (no optimizer, no sweep). Used for characterisation — GHZ states, Bell pairs, the FiQCI examples. Three ingestion paths:

Path A — QPY file (primary)

# Save your circuit as QPY
from qiskit.qpy import dump
with open("my_circuit.qpy", "wb") as f:
    dump([my_circuit], f)

Path B — Python script (no-arg build)

# examples/fiqci/build_fiqci_circuits.py
def build_circuit():
    qc = QuantumCircuit(3)
    qc.h(0); qc.cx(0, 1); qc.cx(1, 2)
    return qc

Path C — QASM string

OPENQASM 3;
include "stdgates.inc";
qubit[3] q;
h q[0]; cx q[0], q[1]; cx q[1], q[2];

Mode 2 — parameterized circuit factory + sweep YAML SPEC-002 §7.5 / D3 — in progress

The headline researcher workflow: supply a pure circuit-factory .py (a build function that takes all parameters as keyword arguments) plus a sweep YAML of the parameter values to sweep. HPCQC builds one circuit per grid point, solves placements from the circuit's own connectivity, runs each under the requested noise (including real Q50 device_calibrated), and computes the counts→autocorrelator observable — averaging across seeds.

Status. The build seam (Gap A), per-placement device-calibrated noise (F5a / D3.2), and device_calibrated routing (D3.3) are landed. The counts execution branch (D3.4) and the bit-exact Floquet reproduction (D3.5) are in progress on feature/device-calibrated-noise. The factory contract and YAML schema below are stable; end-to-end execution lands with D3.4.

The factory contract

The factory exposes a pure, keyword-only build function:

# examples/byo/floquet_dtc.py
def build_circuit(*, num_kicks, epsilon, num_qubits,
                  hz_angles, Jzz_angles, init_bit_array) -> QuantumCircuit:
    h_x = (1.0 - epsilon) * np.pi          # derived constants computed here
    qc = QuantumCircuit(num_qubits, num_qubits)
    for w in range(num_qubits):
        if init_bit_array[w] == 1: qc.x(w)
    for _ in range(num_kicks):
        for w in range(num_qubits):      qc.rx(h_x, w)
        for w in range(num_qubits):      qc.rz(hz_angles[w], w)
        for w in range(num_qubits - 1):  qc.rzz(Jzz_angles[w], w, w + 1)
    qc.measure(range(num_qubits), range(num_qubits))
    return qc
  • Keyword-only (note the *): the signature is validated against your YAML keys at submit time; mismatches fail loud.
  • Pure — no build-time randomness or global state. Disorder enters as arguments, resolved once per seed and shared across the grid. A cross-grid identity check builds two grid points and compares their disorder-bearing gates; a factory that draws RNG inside the build yields differing signatures and the sweep raises before running.
  • num_kicks=0 is legal — the t=0 autocorrelator reference (an init-only circuit, empty disorder signature).

The sweep YAML

# examples/byo/floquet_byo_sweep.yaml
sweep:
  experiments:
    - type: byo_circuit
      circuit_script: examples/byo/floquet_dtc.py
      circuit_function: build_circuit
      fixed: {num_qubits: 4, epsilon: 0.03}
      grid:
        num_kicks: {range: [0, 60]}          # stop-exclusive -> 0..59; incl. t=0
      disorder:
        source: file                          # file | generate
        file: examples/byo/floquet_disorder_q4.json
        initial_state: 3
      disorder_gates: [rz, rzz]               # gates carrying disorder (cross-grid check)
      seed_list: [0, 1, 2]                    # gate instances -> averaged
      noise_configs: [device_calibrated, noiseless]   # opt-in by name
  calibrations:
    - examples/q50_calibration_20260524_08c3c70f.json

Migrating an existing research script into this shape (factory + YAML + per-seed disorder) is walked through end-to-end in examples/byo/MIGRATION_FloquetDTC.md — taking the standalone Floquet_DTC_AK7.py discrete-time-crystal driver to floquet_dtc.py + floquet_byo_sweep.yaml, with emphasis on the purity refactor (moving the per-instance np.random disorder out of the build into per-seed data).

Known issues

F3/F4/F7 fingerprinting columns null for characterisation sweeps

Three Pauli-group-dependent features (z_group_expectation_mean, xz_expectation_ratio, expectation_variance_across_groups) require per-Pauli-group data from VQE measurement stats. These are null for eval-only characterisation sweeps (no measurement stats captured). They will be populated when VQE sweep campaigns run with capture_measurement_stats: true.

T1/T2 scaling alone has no effect on circuits without idle gates

Thermal relaxation noise applies to id and delay instructions. Simple circuits (GHZ = H + CX) have no idle gates, so T1/T2 perturbation alone doesn't change the noise model's effect. Use gate error or readout perturbation for observable differences on shallow circuits.

Container nonlocal limitation

The LUMI Singularity container's Python does not support nonlocal in module-scope nested functions. Use mutable list pattern: counter = [0] and counter[0] += 1.

device_calibrated execution is in progress (D3.4)

The device_calibrated noise source is registered and validated (D3.3), and per-placement noise composition is wired at the device layer (F5a / D3.2), but the BYO counts execution branch that runs it is not yet landed (D3.4). Requesting device_calibrated in a sweep today raises a clear NotImplementedError rather than running it through the synthetic-channel battery. Until D3.4 lands, multi-placement device_calibrated is additionally guarded to a single (top_1) placement with a noise_placement_independent flag, so a placement-blind run is never read as placement-resolved. Tracked as DEBT D3a.
